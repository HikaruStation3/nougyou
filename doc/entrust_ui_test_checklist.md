## 2. 主线：建立委托（API-087）

1. farmer02 标签页：右上角头像 → **委托销售**。
2. 页面标题「委托销售」，右侧按钮「建立委托关系」。
3. 点「建立委托关系」，弹窗里依次填：
   - 被委托商品：**百花土蜂蜜（500g）（库存 46）**
   - 受托方：**吴叔山货铺（绿野农场）**
   - 受托方分成：**15**
   - 结算周期：**按月**
   - 生效开始：今天
   - 生效结束：留空
   - 约定说明：`页面测试：土蜂蜜委托吴叔代销`
4. 点「提交」。

**该看到**：

- 绿色提示「委托关系已发起，等待受托方确认」；
- 自动回到「我委托出去的」Tab，第一条就是刚建的；
- 委托编号 `WT` + 8 位日期 + 4 位数字，例如 `WT202611266323`；
- 状态标签是**橙色「待确认」**；
- 操作列有「统计」「结算单」「终止」，**没有**「接受/拒绝」。

5. **反向验证**：立刻再点「建立委托关系」，还选土蜂蜜 → 提交。
   - **该看到**：红色提示「该商品已有待确认或生效中的委托关系，请先终止后再委托」。

> 抄下委托编号：`________________`

## 4. 主线：代销成交 → 统计变化（API-093 + 订单模块）

> 这一段是模块的核心，答辩必演。用现成的 #3（收纳篮，30%）演示，不用新单。

1. 记下基线：farmer02 或 farmer03 → 委托销售 → 收纳篮那行点「统计」。
   - **该看到**：代销销量 `0`、代销销售额 `￥0.00`、委托方分成 `￥0.00`、受托方分成 `￥0.00`；当前库存 `25`；商品累计销量 `31`。
   - 关掉弹窗。
2. buyer01 标签页：顶部「农产品商城」→ 点「手工竹编收纳篮」。
   - 商品详情页的店铺仍显示**「云岭茶庄」（商品原主蔡伯）**，页面**不会**改成受托方，这是正常的；
   - 代销关系体现在**下单之后**的订单归属上，不在商品页。
3. 数量改 **2** → 立即购买 → 填收货信息（沈明 / 13800138000 / 莆田市仙游县钟山镇湖亭村 3 号）→ 提交订单。
4. **该看到**：提示「已提交 1 个订单」；订单列表里这笔单的店铺变成**「绿野农场」**，明细旁有绿色「委托代销」标签。这是"订单归受托方"的直接证据。
5. 去支付：订单详情 →「去支付」→ 确定。
6. 回商品详情页刷新：库存 25 → **23**。
7. 切 farmer01 → 委托销售 → 收纳篮「统计」。
   - **该看到**：代销销量 `2`、销售额 `￥84.00`、委托方分成 `￥58.80`、受托方分成 `￥25.20`。
   - 验算：84 × 30% = 25.20；84 − 25.20 = 58.80。
8. 切 farmer03（委托方本人）→ 同一条「统计」：**12 项数字与 farmer01 完全一样**。

> 如果第 7 步没变化，先确认第 5 步支付成功（订单状态「待发货」），未支付不计入统计。

9. **未支付不计入**：再下一单收纳篮 ×1，**不支付**，回统计：仍是 `2 / ￥84.00`。
10. 把这笔未支付单取消（我的订单 → 待付款 → 取消订单），商品库存回到 23。

- [ ] 代销归属 + 统计口径 通过

## 5. 主线：管理员生成结算（API-095）

1. 管理端 http://localhost:3000 → 登录 admin + 验证码。
2. 左侧「系统管理」→「**委托结算**」。
3. 搜索框输入 `收纳篮` → 查询：命中 1 条，委托关系「蔡伯土产 → 吴叔山货铺」，分成 30%。
4. 点「生成结算」→ 弹窗核对：委托编号、商品、关系、分成 30%。
5. 结算月份选**本月**（如 2026-11）→「生成结算单」。
6. **该看到**：提示「2026-11 结算单已生成」。
7. 点「结算记录」：
   - 月份 2026-11；
   - 销量 2、销售额 ￥84.00、退单 0、退款 ￥0.00；
   - 委托方应得 **￥58.80**、受托方应得 **￥25.20**；
   - 状态「已结算」，结算时间有值。
8. 再点一次「生成结算」→ 同月 → 提交。
   - **该看到**：红色提示「该委托关系 2026-11 的结算单已生成，请勿重复结算」。
9. 切 farmer02 → 委托销售 → 收纳篮「结算单」：能看到刚生成的这条，数字一致。

## 11. 五个容易卡住的地方

1. **弹窗里找不到想委托的商品**：下拉只列**自己店铺**的商品；商品不在列表里说明不是你的。
2. **提交报"已有待确认或生效中的委托关系"**：该商品已被占用。换商品，或先把旧关系终止。当前土蜂蜜、绿茶、土鸡蛋是空闲的。
3. **接受了委托，下单还是不归受托方**：先看该商品是否有**两条以上**生效委托（地瓜干就是），系统要求"唯一生效"才代销。
4. **统计一直是 0**：订单没支付，或订单已被取消。统计只认「已支付 + 未取消」。
5. **想恢复数据**：手工测试会真实写库（委托、订单、结算单都会留痕）。答辩前重新导入 `doc/zhongshan_farm_init.sql`，**导入前先备份**（当前库与 SQL 的商品数量不一致）。
