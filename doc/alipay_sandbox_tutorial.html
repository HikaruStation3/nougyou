一、做成了什么先看结果，再看步骤

订单模块原来的支付是「模拟支付」：点一下直接把 pay_status 改成 1，pay_type 只是记个数字，没有任何真实支付链路。现在补上了支付宝电脑网站支付（沙箱环境）：浏览器会真正跳到支付宝收银台，用沙箱虚拟买家账号付款，回来向后端主动查单、验签、落库。

能力说明
跳转收银台后端拼参数 + 应用私钥签名，返回完整 GET 地址，前端整页跳转
同步回跳付款后支付宝 302 把浏览器带回 http://localhost:3100/#/pay/result
主动查单结果页读 out_trade_no，调 /query 回查交易状态，验签通过才落库
异步通知/notify 验签 + 校验金额，部署到公网后自动接管
支付方式展示pay_type=2 显示「支付宝（沙箱）」，订单详情多一行支付宝交易号
开关保护没配密钥时自动隐藏入口，只走模拟支付，不影响其它模块演示

支付链路（为什么本机没有公网也能跑通）

① 订单页点「去支付」
选支付宝沙箱
→
② 后端签名/page 返回
收银台地址
→
③ 支付宝收银台沙箱买家账号

④ 跳回结果页带 out_trade_no

→
⑤ 主动查单/query 验签

原理

支付宝的 notify_url 是服务器之间的调用，必须是公网可达地址，本机 localhost 收不到。所以主链路设计成「同步跳回 + 主动查单」：return_url 由浏览器发起，localhost 完全没问题。部署到公网后把 notify-url 换成真实域名，异步通知会自动接管，/query 仍可作为兜底。

二、三个密钥，先分清这一节看懂，后面 90% 的报错都能自己排

支付宝接口全是「你用私钥签名，支付宝用公钥验签；支付宝用它的私钥签名，你用它的公钥验签」。所以本地需要三个东西：

① APPID 沙箱应用身份证，形如 9021000xxxxxxxxx。 来源：开放平台沙箱页面直接复制
② 应用私钥 你在本地生成，只留在自己电脑上，用于后端签名。 来源：密钥工具生成后导出，绝不上传、不外发
③ 支付宝公钥 支付宝那边生成，后端用它验证支付宝返回的响应和通知。 来源：沙箱页面「接口加签方式」保存后显示
④（中间产物）应用公钥 由应用私钥导出，粘到沙箱页面保存，让支付宝能验你的签名。 它不填进项目配置
最容易搞错

配置里的 alipay-public-key 要填支付宝公钥，不是应用公钥。填错的表现是：能跳收银台、也能付款，但回来查单报「响应验签失败」—— 因为收银台跳转只用你的私钥签名（支付宝验你），而查单是验支付宝的签名（你验支付宝），两件事用的是不同密钥。

三、拿到 APPID 与密钥开放平台 → 沙箱 → 自定义密钥

  1. 登录开放平台：打开 open.alipay.com，用支付宝账号登录（个人账号即可，沙箱不需要企业资质）。
  2. 进沙箱应用页：右上角「控制台」→ 左侧「沙箱」；部分账号在「开发工具 → 沙箱」。页面顶部就能看到 APPID，复制下来，这是参数 ①。
    提示

    沙箱和正式环境是两套完全独立的 APPID / 密钥 / 买家账号，不要混用。用正式 APPID 连沙箱网关会报「无效的AppID参数」。

  3. 设置加签方式：同一页找到「开发信息 → 接口加签方式」，选 自定义密钥（若已设置则点「查看/修改」）。加密方式选 RSA2，密钥长度 2048。
  4. 用密钥工具生成：页面会给出「支付宝开放平台密钥工具」的下载入口（也可在开放平台文档中心搜「密钥工具」，Windows / macOS 都有）。
    • 打开工具 → 密钥格式 PKCS#8（JAVA 适用） → 密钥长度 2048 → 生成密钥
    • 复制 应用私钥，先存到一个本地文本文件（后面要贴进配置）
    • 复制 应用公钥，粘贴回沙箱页面 → 保存
  5. 复制支付宝公钥：保存成功后，同一块区域会显示 支付宝公钥（注意不是上面那个应用公钥），复制下来，这是参数 ③。
格式坑

密钥工具里如果选了 PKCS#1（非 JAVA 适用），导出的私钥后端解析会失败，报「私钥格式错误 / InvalidKeySpec」。一定选 PKCS#8。本项目两种写法都支持：带 -----BEGIN PRIVATE KEY----- 头尾的多行 PEM，或去掉头尾的单行 Base64。

四、拿沙箱买家账号演示付款时用它登录收银台

沙箱页面下方有「沙箱账号」区域，分为买家和商家。买家账号一般长这样：

项示例用途
买家账号rqfbtj9407@sandbox.com收银台登录用
登录密码111111登录收银台
支付密码111111确认付款时输入
账户余额页面可「充值」虚拟金额余额不足时先充值
放心

沙箱里的一切都是虚拟账目，付款不会产生任何真实扣款，也不需要绑真实银行卡。

五、写配置改 application.yml 或注入环境变量

方式 A：直接改 application.yml（最直观，适合答辩固定环境）

打开 backend/src/main/resources/application.yml，找到文件末尾的 alipay: 段：

alipay:
  enabled: true                                    # ← 关键开关，默认 false
  sandbox: true
  gateway: https://openapi-sandbox.dl.alipaydev.com/gateway.do
  app-id: 9021000xxxxxxxxx                         # 参数 ①
  private-key: "MIIEvQIBADANBgkq...你的应用私钥"     # 参数 ②，单行 Base64
  alipay-public-key: "MIIBIjANBgkqhkiG...支付宝公钥" # 参数 ③，注意不是应用公钥
  notify-url: http://localhost:8080/api/v1/pay/alipay/notify
  return-url: http://localhost:3100/#/pay/result
  subject-prefix: 钟山镇扶贫助农-

方式 B：环境变量（不把密钥写进代码，答辩前临时注入）

Spring Boot 的环境变量优先级高于 yml，改完不用动文件、重启即生效。PowerShell 里：

$env:JAVA_HOME   = "D:\Program Files\Java\jdk-21.0.13.1"
$env:ALIPAY_ENABLED     = "true"
$env:ALIPAY_APP_ID      = "9021000xxxxxxxxx"
$env:ALIPAY_PRIVATE_KEY = "MIIEvQIBADANBgkq..."
$env:ALIPAY_PUBLIC_KEY  = "MIIBIjANBgkqhkiG..."
$env:ALIPAY_RETURN_URL  = "http://localhost:3100/#/pay/result"

& "D:\Program Files\Apache\maven\bin\mvn.cmd" -o "-Dmaven.repo.local=D:\dev\m2repo" spring-boot:run
注意

密钥是 Base64，含 + / =，写进 YAML 时整行加引号，否则 : 和特殊字符会导致解析异常。用环境变量就不存在这个问题。

两个 URL 别写反：return-url 是前端页面（3100，带 #/pay/result），notify-url 是后端接口（8080）。

六、确认数据库字段orders.trade_no

支付成功后要把支付宝交易号落库，orders 表需要一个 trade_no 字段。已经加过的库跳过这步，没加过的执行：

ALTER TABLE orders
  ADD COLUMN trade_no VARCHAR(64) NULL COMMENT '支付宝交易号（模拟支付为空）'
  AFTER pay_time;

-- 确认
SHOW COLUMNS FROM orders LIKE 'trade_no';

MySQL 客户端（本项目本机路径）：

七、启动并自检先确认后端认到了密钥

  1. 按原来的方式启动后端（8080）。启动日志里搜 Tomcat started 确认起来了。
  2. 调自检接口 —— 这个接口不需要登录，专门用来确认配置是否配对：
curl http://localhost:8080/api/v1/pay/alipay/config

配好了应该长这样：

{
  "code": 200,
  "data": {
    "enabled": true,
    "ready": true,
    "sandbox": true,
    "gateway": "https://openapi-sandbox.dl.alipaydev.com/gateway.do",
    "returnUrl": "http://localhost:3100/#/pay/result",
    "missing": ""
  }
}

没配好时 ready 为 false，missing 会直接告诉缺哪几项，例如 app-id alipay-public-key，不用去翻日志。

前端逻辑

门户点「去支付」时会先调一次这个接口（结果在内存里缓存）：ready=true 才弹出「支付宝沙箱 / 模拟支付」二选一；ready=false 直接走模拟支付，并在弹窗里用小字提示缺哪几项。所以没配密钥也不会把演示卡住。

八、走一遍完整支付从加购物车到订单详情

  1. 买家登录门户：http://localhost:3100，用 buyer01 / 123456。
  2. 下单：加购物车 → 结算 → 支付方式选「支付宝（沙箱）」→ 提交订单（此时订单是待付款）。
  3. 发起支付：订单列表点「去支付」→ 弹窗里点 「支付宝沙箱」按钮（点「模拟支付」则走旧逻辑，方便随时对照演示）。
  4. 收银台付款：浏览器整页跳到支付宝沙箱收银台 → 用沙箱买家账号登录 → 输入支付密码 → 确认付款。
    别慌

    收银台上显示的是「沙箱环境」字样，商品标题是 钟山镇扶贫助农-订单号，金额是订单实付金额。

  5. 自动跳回：付款成功后支付宝把浏览器带回 http://localhost:3100/#/pay/result?out_trade_no=...，页面显示「正在确认支付结果…」。
  6. 结果页判定：
    • 查到 TRADE_SUCCESS → 显示「支付成功」，订单置为待发货，交易号落库
    • 还没付 / 支付宝侧有 1~3 秒延迟 → 显示「尚未完成支付」，可点「重新查询」（会连查 3 次，间隔 2 秒）
    • 验签失败 → 显示「查询支付结果失败」并给出原因
  7. 回订单详情核对：支付方式显示 支付宝（沙箱），多出一行 支付宝交易号，状态待发货。
  8. 商家侧联动：换 farmer01 登录，订单出现在待发货列表，可执行发货 —— 说明支付链路和后续流程是通的。
实测记录

本项目实测：自签密钥下待签名串的排序与剔除规则正确；用支付宝公钥验签收银台回跳 URL 通过、篡改 1 个参数即失败；模拟支付宝私钥推送 notify 返回 success，pay_type=2、trade_no 正确落库；重复通知只生效一次（幂等）；金额 0.01 与订单 152.00 不符时返回 failure。

十一、答辩可讲的技术点这段可以直接说

1）没有引入官方 SDK。官方 alipay-sdk-java 是个约 40MB 的胖 jar，还带 fastjson、bcprov、dom4j、okhttp 一堆传递依赖；本项目用的是离线 Maven 仓库，装它成本很高。支付宝接口本质就是「拼参数 + RSA2 签名 + HTTP 表单」，所以直接用 JDK 自带的 SHA256withRSA 和 HttpClient 实现，代码全在 com.nougyou.payment，一共 6 个类，看得见、改得动。

2）签名串规则。待签名内容 = 除 sign、sign_type 之外的所有非空参数，按参数名 ASCII 升序 拼成 k=v&k=v（值不做 URL 编码），再 SHA256withRSA 签名后 Base64。少一个参数、多一个空值、顺序错一个，都会导致验签失败 —— 这是支付宝接入最典型的坑。

3）验签必须用原文。alipay.trade.query 的响应是 {"alipay_trade_query_response":{...},"sign":"..."}，验签对象是 response 节点的原始 JSON 文本。如果先反序列化成对象再序列化回去，字段顺序一变签名就对不上，所以代码里按大括号配对（跳过字符串内的括号）原样截取那一段再验签。

4）先判业务码，再验签。APPID 填错时支付宝返回的是错误报文、未必带签名。如果先验签，就会把「app_id 不合法」误报成「公钥配错」，排查方向直接跑偏。所以先看 code != 10000 直接把 sub_msg 抛给前端，验签放在后面。

5）幂等与安全。markPaidByAlipay 用的是带 pay_status=0 条件的 UPDATE，重复通知、重复查单只会生效一次；落库前比对 total_amount 与订单应付金额，不一致直接拒绝；/page 先校验订单归属，只能给自己的订单生成支付链接。

6）容错设计。支付通道做成可插拔的「开关 + 探测」：没配密钥时接口明确报错、前端自动降级到模拟支付，保证答辩现场网络或账号出问题也能完整演示其它模块。
