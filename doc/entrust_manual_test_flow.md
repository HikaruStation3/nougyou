# 委托销售模块 · 手工测试操作流程

> 全程点鼠标，不写代码、不调接口、不跑任何测试脚本。
> 唯一需要"敲"的是第 0 节把系统启动起来的三行启动命令，那是开系统，不是测试。
> 主线一条链走完约 15 分钟，答辩演示取第 3~10 步即可（约 6 分钟）。

---

## 0. 先把系统开起来（约 3 分钟）

只需要开三个黑窗口，每个窗口敲一行，敲完就别关了。**如果系统已经在跑，直接跳到第 1 节。**

开窗顺序不能反：先数据库，再后端，最后两个前端页面。

### 第 1 个窗口：数据库

在项目根目录 `C:\Users\61074\Desktop\毕设\code\nougyou` 下执行：

```
docker compose up -d mysql
```

等 20 秒左右。**怎么算起来了**：执行 `docker ps`，能看到 `nougyou-mysql` 那一行，状态是 `Up`。

> 如果你本机本来就装着 MySQL 并占用 3306，这一步可以跳过，只要库 `nougyou` 在就行。

### 第 2 个窗口：后端

进到 `backend` 目录（项目根目录下的 backend 文件夹），执行：

```
mvn spring-boot:run
```

**怎么算起来了**：窗口里滚完一堆日志后，最后出现 `Started ... on port 8080`，并且停在那儿不退出。
这一步最慢，第一次要等 1~3 分钟。**这个窗口从头到尾不能关**，关了就整个系统挂掉。

### 第 3 个窗口：起两个前端页面

门户（农户/买家用的）和管理后台（admin 用的）是两个不同的页面，要分别起。可以再开两个窗口：

门户 —— 进 `portal` 目录：

```
npm run dev
```

管理后台 —— 进 `frontend` 目录：

```
pnpm dev
```

> 管理后台的依赖管理器限定为 pnpm，用 npm 会直接报错停下来，这是正常的。第一次跑要先 `pnpm install`。

**怎么算起来了**：浏览器打开下面两个地址，能出页面就成：

| 页面 | 地址 | 打开了应该看到 |
|---|---|---|
| 门户 | http://localhost:3100 | 农产品商城首页，右上角有"登录" |
| 管理后台 | http://localhost:3000 | 蓝白配色的登录页 |

> 只有 3100 和 3000 这两个是给人点的。8080 是后端，别直接访问。

## 1. 开测准备（5 分钟，别省）

### 1.1 开 4 个浏览器标签页，各登一个号

登录态是按标签页隔离的，所以不用来回退出登录，四个身份同时在线。

| 标签页 | 打开 | 账号 | 密码 | 这个号在测试里演谁 |
|---|---|---|---|---|
| ① | http://localhost:3100 | `farmer02` | `123456` | **委托方**（秀兰农场，土蜂蜜的主人） |
| ② | http://localhost:3100 | `farmer01` | `123456` | **受托方**（吴叔山货铺，帮忙代卖的人） |
| ③ | http://localhost:3100 | `buyer01` | `123456` | **买家**（下单的人） |
| ④ | http://localhost:3000 | `admin` | `123456` | **管理员**（生成结算单的人） |

三个注意点：

1. **每次登录都要输 4 位图形验证码**。验证码看不清就点一下图片换一张。
2. 登录成功后默认落在"个人中心"，不是首页，别以为登错了。
3. **委托销售入口在右上角头像的下拉菜单里**，菜单项叫「委托销售」。买家账号看不到这一项，这是对的。

如果密码报错，先确认是 `123456`（不是 123456）。

### 1.2 认准这次用哪个商品

整个流程只用一个商品：**百花土蜂蜜（500g）**，单价 **￥68**，属于 farmer02（秀兰农场）。

为什么是它：它当前没有任何"待确认 / 生效中"的委托，是空闲的。选错商品会在第 1 步直接报"该商品已有委托关系"。

以下三个商品**本次不要碰**：

| 商品 | 为什么别用 |
|---|---|
| 蔡伯手工地瓜干 | 上面挂着两条都生效的委托，会导致代销完全失效，讲不清 |
| 钟山农家山茶油 / 钟山笋干 | 已经被别的委托占用了，建不进去 |
| 手工竹编收纳篮 | 已经有一条生效委托，是"现成样本"，留给第 11 步当对照 |

### 1.3 先记下三个数字（后面全靠对比判定）

进 ① farmer02 标签页 → 头像 → 委托销售，看一眼就行，然后记下来：

| 要记的数字 | 现在应该是 | 你实际看到的 |
|---|---|---|
| 土蜂蜜的库存 | 46（以你屏幕上的为准） | ______ |
| 土蜂蜜的累计销量 | 随便，记下来就行 | ______ |
| 委托列表里有没有土蜂蜜的生效委托 | 没有 | ______ |

**判定原则：后面每一步都不看文字描述，只看这三个数字怎么变。** 页面提示语可能改，数字不会骗人。

### 第 1 步 · 建立委托（farmer02）

**操作**

1. 切到 ① farmer02 标签页，点右上角头像 →「委托销售」。
2. 页面标题是「委托销售」，右上角有个蓝色按钮「建立委托关系」，点它。
3. 弹出「建立委托关系」对话框，从上到下依次填：

| 字段 | 填什么 | 注意 |
|---|---|---|
| 被委托商品 | 选「百花土蜂蜜（500g）（库存 46）」 | 下拉里**只有你自己的商品**，找不到就说明这商品不是 farmer02 的 |
| 受托方 | 选「吴叔山货铺（绿野农场）」 | 下拉里**不会出现你自己**，这是对的 |
| 受托方分成 | 填 `15` | 单位是 %，意思是卖 100 块吴叔拿 15 块 |
| 结算周期 | 选「按月」 | 三个选项：按月 / 按季 / 按单 |
| 生效开始 | 默认就是今天，不动 | |
| 生效结束 | **留空** | 留空 = 长期有效 |
| 约定说明 | `页面测试：土蜂蜜委托吴叔代销` | 最多 500 字 |

4. 点右下角「提交」。

**该看到（四条全中才算过）**

- 顶部弹绿条：`委托关系已发起，等待受托方确认`；
- 对话框自动关闭，页面自动切回「我委托出去的」这个 Tab；
- 列表第一条就是刚建的那条，委托编号长这样 `WT202611266323`（WT + 8 位日期 + 4 位数字）；
- 状态那一列是**橙色「待确认」**；操作列只有「统计」「结算单」「终止」三个链接，**没有「接受 / 拒绝」**。

> 把委托编号抄下来：`________________`

### 第 2 步 · 重复建立应该被拦住（farmer02，30 秒）

**为什么测**：一个商品同时只能有一条待确认或生效中的委托，这是整个模块最容易崩的规则。

**操作**：不要刷新页面，直接再点一次「建立委托关系」，商品**还选土蜂蜜**，其他随便填，点「提交」。

**该看到**：红条提示 `该商品已有待确认或生效中的委托关系，请先终止后再委托`，对话框不关、提交不出去。

- [ ] 第 2 步通过（这条拦住，说明后面统计才不会串账）

### 第 3 步 · 受托方接受（farmer01）

**操作**

1. 切到 ② farmer01 标签页，头像 →「委托销售」。
2. 点上面第二个 Tab「**我代销的**」。
3. 左边状态下拉选「待确认」→ 点「查询」。
4. 列表里应该出现「百花土蜂蜜」，状态「待确认」，操作列有绿色的「接受」和红色的「拒绝」。
5. 点「接受」→ 弹框问 `确认接受「百花土蜂蜜（500g）」的代销委托？` → 点「确定」。

**该看到**

- 绿条：`已接受委托，关系即时生效`；
- 这一行的状态从橙色「待确认」变成**绿色「生效中」**；
- 「接受 / 拒绝」两个按钮**消失**了（因为已经处理过）。

> 如果列表是空的：确认 Tab 是不是切到了「我代销的」（不是「我委托出去的」），以及状态下拉是不是「待确认」。

- [ ] 第 3 步通过

### 第 4 步 · 回委托方确认关系生效（farmer02，1 分钟）

**操作**：切回 ① farmer02 →「我委托出去的」→ 点一下「查询」刷新。

**该看到**：同一条委托编号的那行，状态也变成了**绿色「生效中」**，受托方那一列显示「吴叔山货铺」。

**这一步的意义**：同一条数据两边都能看到、且状态同步 —— 说明委托关系是真生效了，不是只改了个标签。

- [ ] 第 4 步通过

### 第 5 步 · 买家下单（buyer01）★ 关键证据在这里

**操作**

1. 切到 ③ buyer01 标签页，点顶部「农产品商城」，找到「百花土蜂蜜（500g）」点进去。
2. 商品详情页的店铺显示的是**「鲜果合作社」**（原主秀兰的店）—— **这是正常的，不是 bug**。代销关系不体现在商品页上。
3. 数量改成 **1** → 点「立即购买」。
4. 填收货信息（随便填真实格式即可）：
   - 收货人：`沈明`
   - 手机：`13800138000`
   - 地址：`莆田市仙游县钟山镇湖亭村3号`
5. 点「提交订单」。

**该看到（这是整个模块最值钱的判定点）**

- 提示 `已提交 1 个订单`；
- 打开「我的订单」，这笔订单的店铺变成了 **「绿野农场」**（不是鲜果合作社）；
- 订单明细旁边有一个「委托代销」标记。

> **订单的店从"鲜果合作社"变成"绿野农场"，就是"这笔生意算在受托方头上"的铁证。**
> 答辩时把这一屏和商品详情页放一起对比，效果最好。

6. 顺手回商品详情页刷一下：库存应该从 46 变成 **45**（下单先把货占住了，还没付钱）。

- [ ] 第 5 步通过

### 第 6 步 · 支付（buyer01，1 分钟）

**操作**：我的订单 → 找到这笔 →「去支付」→ 确认支付（走的是模拟支付，不用真付钱）。

**该看到**：订单状态变成「待发货」。

**然后回头核对一件事**：这时候再去看委托销售 → 统计，数字应该**还是 0**。

**为什么**：统计只认「已支付」的订单。支付这一步做完才算数，下单不算。这条很多人会当成 bug 报，其实是对的。

- [ ] 第 6 步通过

---

### 第 7 步 · 看统计（farmer01，30 秒）★ 算账

**操作**：② farmer01 → 委托销售 →「我代销的」→ 土蜂蜜那行点「统计」。

弹出「委托销售统计」窗口，12 项数字。**只需要盯这 4 个**：

| 项目 | 应该是 | 怎么算出来的 |
|---|---|---|
| 代销销量 | `1` | 买了 1 件 |
| 代销销售额 | `￥68.00` | 1 × 68 |
| 委托方分成收入 | `￥57.80` | 68 ×（100−15）% |
| 受托方分成收入 | `￥10.20` | 68 × 15% |

**顺手验算一句**：`57.80 + 10.20 = 68.00`。两个分成加起来必须正好等于销售额，差一分都算不过。

另外两个数字别误读：

- **当前库存** 现在应该是 45（下过单，占掉了）；
- **商品累计销量** 还是老数字（发货时才累加），跟「代销销量」不是一个东西，两个数不一样是正常的。

- [ ] 第 7 步通过

---

### 第 8 步 · 双端对照（farmer02，30 秒）

**操作**：切到 ① farmer02 →「我委托出去的」→ 同一条委托 →「统计」。

**该看到**：12 个数字和 farmer01 看到的**一模一样**，尤其是 68.00 / 57.80 / 10.20 这三个。

**这一步在证明什么**：委托方和受托方看的是同一份数据（数据库视图算的），不存在"各算各的、对不上账"。

- [ ] 第 8 步通过

### 第 9 步 · 管理员生成结算单（admin）★ 收口

**操作**

1. 切到 ④ 管理后台（3000）标签页。
2. 左侧菜单「系统管理」→「**委托结算**」。
3. 搜索框输入 `土蜂蜜` → 点查询。应该命中 1 条：「秀兰农场 → 吴叔山货铺」，分成 15%。
4. 这一行点「生成结算」。
5. 弹窗里核对：委托编号、商品、双方、分成 15% —— 都对得上再往下走。
6. 结算月份选**本月**（默认就是当月，如 2026-11）→ 点「生成结算单」。

**该看到**

- 提示 `2026-11 结算单已生成`；
- 点「结算记录」，能看到这一条，数字是：销量 1、销售额 ￥68.00、退单 0、退款 ￥0.00、委托方应得 **￥57.80**、受托方应得 **￥10.20**、状态「已结算」、结算时间有值。

7. **再点一次「生成结算」**，还是本月，提交。
   - **该看到**：红条 `该委托关系 2026-11 的结算单已生成，请勿重复结算`。

> 第 7 小步是重点：同一条关系同一个月不能重复结算，不然钱会算两遍。

- [ ] 第 9 步通过

### 第 10 步 · 商家侧能看到结算单（farmer02，30 秒）

**操作**：① farmer02 → 委托销售 → 土蜂蜜那行 →「结算单」。

**该看到**：表格里出现 2026-11 这条，销量 1、销售额 ￥68.00、委托方应得 ￥57.80、受托方应得 ￥10.20、状态「已结算」。

**没生成之前**这里应该是「暂无结算单，待管理员按月生成」的空状态 —— 如果你在第 9 步之前顺手点过，应该见过这个空状态，两个状态一对比就完整了。

- [ ] 第 10 步通过

---

### 第 11 步 · 终止，并验证"真的不再代销"（farmer02 + buyer01）★ 最容易糊弄过去的一步

**操作**

1. ① farmer02 →「我委托出去的」→ 土蜂蜜那行点「终止」。
2. 弹框让填原因（可以留空），填 `测试结束，暂停代销` → 确定。
3. **该看到**：绿条 `委托关系已终止`；状态变**灰色「已终止」**；「终止」按钮消失；"有效期"那一列的后半段变成**今天**（哪怕原来的结束日是明年）。

**关键验证（很多人只做到第 3 小步就收工了，其实没验到）**

4. 切到 ③ buyer01，**再买一单**土蜂蜜，还是 1 件，提交订单。
5. **该看到**：这笔新订单的店铺是 **「鲜果合作社」**（回到商品原主），**而不是**「绿野农场」，明细旁也**没有**「委托代销」标记。
6. 回 farmer01 的统计：数字**停在 1 件 / ￥68.00 不动**（历史保留，新单不再计入）。

> 第 5 小步才是"终止生效"的硬证据。只看到状态标签变灰，说明不了系统真的停止代销了。
> 这单新订单不付款，测完直接取消掉，库存会回到 45。

- [ ] 第 11 步通过

## 3. 分支：拒绝流程（单独 3 分钟）

主线走完了，再花 3 分钟把"拒绝"这条岔路走一遍。**换一个商品，别用土蜂蜜**（它刚被终止，虽然也空出来了，但留着当对照更清楚）。

**操作**

1. ① farmer02 →「建立委托关系」→ 商品选「**散养土鸡蛋**」→ 受托方选「**蔡伯土产（云岭茶庄）**」→ 分成 `20` → 提交。
2. 切到 farmer03（**需要临时开第 5 个标签页**登 `farmer03` / `123456`）→ 委托销售 →「我代销的」→ 待确认 → 找到这条 → 点「拒绝」。
3. 弹框要求填原因，**先故意不填直接点确定** → 应该提示 `请填写原因`，提交不出去。
4. 再填 `近期人手不足` → 确定。

**该看到**

- 绿条 `已拒绝该委托`，状态变**红色「已拒绝」**（不是灰色，别和"已终止"搞混）；
- 切回 farmer02，「我委托出去的」这条也是「已拒绝」；点它的「统计」「结算单」，都是空的；
- 这条**不占用商品**：farmer02 再给土鸡蛋建一条新委托，应该能建成功（不会报"已有委托关系"）。

- [ ] 拒绝分支通过

## 5. 通过判定

下面 10 条是**必须过**的，缺一条这个模块就不能算测完：

| # | 判定点 | 过了 |
|---|---|---|
| 1 | 建委托后状态是「待确认」，编号 WT 开头，双方列表都能看到 | ☐ |
| 2 | 同一商品再建一次被拦住 | ☐ |

| 6 | 统计 68.00 = 57.80 + 10.20，比例正好 15% | ☐ |

## 6. 卡住了怎么查（按现象找）

| 现象 | 十有八九是 | 怎么办 |
|---|---|---|
| 3100 / 3000 打不开 | 前端窗口被关了，或端口被占 | 看那两个黑窗口还在不在；重新 `npm run dev` / `pnpm dev` |
| 页面能开但一点就报"网络错误" | 后端窗口挂了，或 8080 没起来 | 看后端窗口有没有 `Started ... on port 8080`；挂了就重启 |
| 登录一直说验证码错 | 验证码区分大小写，且 60 秒过期 | 点图片刷新，重新输，别拖 |
| 下拉里找不到土蜂蜜 | 当前登录的不是 farmer02，或者商品已下架 | 确认头像旁的用户名；商品必须是你自己店里的 |
| 提交报"已有待确认或生效中的委托关系" | 这商品被占了（可能你之前测过没终止） | 先把这个商品现有的委托全部「终止」，再建 |
| 接受了委托，下单还是不归受托方 | 该商品挂着**两条以上**生效委托（地瓜干就是） | 换商品；系统要求"唯一一条生效"才代销 |
| 统计一直是 0 | 订单没支付，或已经取消 | 只认「已支付 + 未取消」，回去把支付做完 |
| 统计数字和商品累计销量对不上 | 这俩不是一回事 | 「代销销量」是这条关系的，「累计销量」是全渠道的，且发货才涨 |
| 明明支付了，累计销量没变 | 还没发货 | 发货才累加，正常 |
| 管理端没有「委托结算」菜单 | 登的不是 admin，或菜单权限没刷出来 | 换成 admin 重新登录 |
| 结算单是「待结算」不是「已结算」 | 你看到的是手工插库的种子数据 | 自己新生成的永远是「已结算」，不用管 |

## 7. 测完复位（答辩前必做）

手工测试会真实写库 —— 委托关系、订单、结算单、库存全都会留下痕迹。答辩前想回到干净状态：

1. **先备份**：`mysqldump -uroot -p123456 nougyou > backup.sql`（不备份别往下走）。
2. 再决定要不要重新导入 `doc/zhongshan_farm_init.sql`。

**注意一个坑**：当前库在售商品只有 7 个，而那份 SQL 里有 10 个 —— 说明现在的库不是它初始化出来的。直接导入会把现有演示数据冲掉，导入前务必确认。

只想清掉本次痕迹、保留种子数据的话，最省事的做法是：把测出来的委托全部「终止」，把测试订单「取消」，剩下的历史数据不影响演示。

## 8. 答辩演示：6 分钟精简版

时间紧就只演这 5 屏，一屏一句话：

1. **farmer02 建立委托** → "农户把卖不动的货委托给同村人代卖，15% 分成"；
2. **farmer01 点接受** → "受托方一键接单，关系即时生效"；

5. **admin 生成结算单** → "按月自动拆账，重复生成会被系统拦住"。

最后补一句"终止后再下单就回到原主"，整条链路就闭环了。
