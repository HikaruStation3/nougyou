# 项目启动手册

钟山镇扶贫助农系统 —— 本地开发环境启动指南。

---

## 1. 项目结构

| 目录 | 说明 | 技术栈 | 默认端口 |
| --- | --- | --- | --- |
| `backend/` | 后端服务 | Spring Boot 3.5 + MyBatis-Plus + Security/JWT + MinIO SDK | 8080 |
| `frontend/` | 管理后台 | Vue 3 + TypeScript + Element Plus + Vite | 3000 |
| `portal/` | 用户门户（游客/买家/农户） | Vue 3 + JavaScript + Element Plus + Vite | 3100 |
| `sql/` | 建表脚本 | MySQL 8 | — |
| `doc/` | 接口文档、演示数据、测试清单 | — | — |
| `scripts/` | 接口冒烟测试脚本（Python） | — | — |

---

## 2. 环境要求

| 依赖 | 版本要求 | 说明 |
| --- | --- | --- |
| JDK | **21**（必须） | `pom.xml` 中 `<java.version>21</java.version>` |
| Maven | 3.9+ | 用于后端打包 |
| Node.js | **≥ 20.19 或 ≥ 22.12**（推荐 22.x） | Vite 7/8 的最低要求，低版本会报 `crypto.hash is not a function` |
| MySQL | 8.x | 默认 `localhost:3306` |
| MinIO | 任意较新版本 | 对象存储，**以原生进程运行，不使用 Docker** |

> 注意：若机器上同时装了多个 JDK / Node，请确认命令实际使用的是 JDK 21 和 Node 22（可用 `java -version`、`node -v` 检查）。

## 3. 第一步：启动 MySQL 并初始化数据库

### 3.1 启动 MySQL

确保 MySQL 服务已运行（默认端口 3306）。默认连接信息见 `backend/src/main/resources/application.yml`：

| 配置项 | 默认值 | 可用环境变量覆盖 |
| --- | --- | --- |
| 主机 | `localhost` | `MYSQL_HOST` |
| 端口 | `3306` | `MYSQL_PORT` |
| 数据库 | `nougyou` | `MYSQL_DB` |
| 用户名 | `root` | `MYSQL_USER` |
| 密码 | `123456` | `MYSQL_PASSWORD` |

### 3.2 初始化表结构与数据（二选一）

**方案 A：全新库 + 演示数据（推荐首次搭建）**

```bash
mysql -u root -p123456 < doc/zhongshan_farm_init.sql
```

该脚本包含完整建表语句与演示数据（商品、订单、用户、权限等）。

**方案 B：仅建表（空库）**

```bash
mysql -u root -p123456 < sql/init.sql
```

> `sql/init.sql` 会创建 `nougyou` 库及全部业务表（含农家乐 `farm_project`），不含演示数据。后续新增模块的权限点由后端启动时的 `DataInitializer` 自动补齐。

## 4. 第二步：启动 MinIO（原生进程）

项目使用 MinIO 存储图片/文件，**不通过 Docker 启动**。

### 4.1 准备

- 可执行文件：`minio.exe`（示例路径 `D:\ART\minio\bin\minio.exe`）
- 数据目录：需可写。本项目默认使用仓库内 `.minio-data`（已加入 `.gitignore`）

### 4.2 启动命令（PowerShell）

```powershell
$env:MINIO_ROOT_USER='minioadmin'
$env:MINIO_ROOT_PASSWORD='minioadmin'
D:\ART\minio\bin\minio.exe server d:\project\nougyou\.minio-data --address ":9000" --console-address ":9001"
```

启动成功标志：`API: http://0.0.0.0:9000  Console: http://0.0.0.0:9001`。

| 项目 | 值 |
| --- | --- |
| API 地址 | http://localhost:9000 |
| 控制台 | http://localhost:9001 |
| 账号 / 密码 | `minioadmin / minioadmin` |
| Bucket | `nougyou`（首次上传时自动创建） |

> 后端配置中的 `minio.*` 支持环境变量覆盖：`MINIO_ENDPOINT`、`MINIO_ACCESS_KEY`、`MINIO_SECRET_KEY`、`MINIO_BUCKET`。

### 4.3 说明

- 后端上传时会自动创建 bucket 并设置 **公共读** 策略，返回固定访问地址 `{endpoint}/{bucket}/{objectName}`，**不会过期**（不使用 7 天预签名地址）。
- 若 MinIO 不可用，文件模块会回退到本地目录 `./uploads`（见 `nougyou.file.local-dir`），由 `/api/v1/files/local/**` 提供访问。
- 健康检查：`http://localhost:9000/minio/health/live` 返回 200 即正常。

## 5. 第三步：启动后端

### 5.1 Maven 配置（重要）

若本机 Maven 全局 `settings.xml` 配置了不可达的私服镜像，直接执行 `mvn` 会报 `Non-resolvable parent POM ... connect timed out`。

仓库根目录已提供可用的 settings 文件：

- `settings-online.xml`：走阿里云镜像（可在线拉取依赖，推荐）
- `settings-offline.xml`：离线模式（依赖已缓存在本地仓库时使用，更快）

**打包时始终显式指定这两个文件。**

### 5.2 打包

```powershell
$env:JAVA_HOME = "D:\ART\jdk\jdk21"   # 换成你的 JDK 21 路径
cd backend
mvn -s ..\settings-online.xml -gs ..\settings-online.xml -DskipTests package
```

产物：`backend/target/nougyou-backend-0.0.1-SNAPSHOT.jar`

> **每次修改后端代码后都必须重新 `package` 再重启**，否则运行的仍是旧 JAR，会出现"接口不存在 / 系统异常"等假故障。

### 5.3 启动

```powershell
cd backend
java -jar target/nougyou-backend-0.0.1-SNAPSHOT.jar --logging.file.name=backend.log
```

启动成功标志：

```
Tomcat started on port 8080 (http)
Started NougyouApplication in x.xxx seconds
HikariPool-1 - Start completed.
```

### 5.4 常用启动参数

| 参数 | 作用 |
| --- | --- |
| `--logging.file.name=backend.log` | 输出日志到文件 |
| `--nougyou.captcha.enabled=false` | **仅开发/接口联调**时关闭登录图形验证码 |
| `--server.port=8081` | 改端口（前端代理需同步修改） |

### 5.5 关键环境变量（可选）

| 变量 | 说明 | 默认 |
| --- | --- | --- |
| `JWT_SECRET` | JWT 签名密钥（≥32 字节，生产必须覆盖） | 内置开发值 |
| `GLM_API_KEY` | 智谱 GLM Key，AI 客服功能需要 | 占位值 |
| `GLM_MODEL` | 模型名 | `glm-4-flash` |
| `LOCAL_UPLOAD_DIR` | 本地文件兜底目录 | `./uploads` |

支付宝沙箱默认关闭（`alipay.enabled=false`），不影响其它功能。

### 5.6 AI 模型（智谱 GLM）Key 配置

AI 客服等能力通过 Spring AI 调用智谱 GLM 的 OpenAI 兼容接口，Key 配置在：

**配置文件**：`backend/src/main/resources/application.yml`

```yaml
spring:
  ai:
    openai:
      # ⚠️ 这里是 AI 模型的 Key（默认占位符，必须替换为真实 Key 才能使用 AI 功能）
      api-key: ${GLM_API_KEY:这里填智谱ai的key}
      base-url: ${GLM_BASE_URL:https://open.bigmodel.cn/api/paas/v4}
      chat:
        completions-path: /chat/completions
        options:
          model: ${GLM_MODEL:glm-4-flash}
          temperature: 0.7

nougyou:
  ai:
    model-name: ${GLM_MODEL:glm-4-flash}
    history-size: 10            # 携带的历史消息条数
    timeout-ms: 180000          # SSE 超时（毫秒）
    max-question-length: 1000   # 单次提问最大字数
```

Key 的获取：登录 [智谱开放平台](https://open.bigmodel.cn/) → 控制台 → API Keys 创建。

#### 推荐的配置方式（按优先级）

**方式一：环境变量（推荐，不污染代码、不会误提交）**

```powershell
$env:GLM_API_KEY = "你的智谱APIKey"
java -jar target/nougyou-backend-0.0.1-SNAPSHOT.jar
```

需要长期生效可写入系统环境变量（`setx GLM_API_KEY "你的key"`），重启终端后生效。

**方式二：启动参数**

```powershell
java -jar target/nougyou-backend-0.0.1-SNAPSHOT.jar --spring.ai.openai.api-key=你的智谱APIKey
```

**方式三：直接改 `application.yml`**

把 `${GLM_API_KEY:这里填智谱ai的key}` 中的占位值替换为真实 Key（**不推荐**：真实 Key 会进入 git 历史）。

#### 可覆盖的相关变量

| 变量 | 说明 | 默认值 |
| --- | --- | --- |
| `GLM_API_KEY` | 智谱 API Key | 占位符（未配置时 AI 功能不可用） |
| `GLM_BASE_URL` | OpenAI 兼容接口地址 | `https://open.bigmodel.cn/api/paas/v4` |
| `GLM_MODEL` | 模型名称 | `glm-4-flash` |

#### 说明

- 未配置真实 Key 时：调用 AI 会返回鉴权失败（401），**不影响其它业务功能**（商品、订单、农家乐等照常使用）。
- AI 客服为 SSE 流式接口，网关/代理需允许长连接（后端已配置 `request-timeout: 180000`）。
- 验证方式：登录用户门户（http://localhost:3100）→ 打开 AI 客服 → 提问，能正常流式返回即配置成功。
- 安全提示：`GLM_API_KEY`、`JWT_SECRET`、支付宝私钥等敏感信息请一律通过环境变量注入，不要提交到仓库。

## 6. 第四步：启动管理后台（frontend）

```powershell
cd frontend
npm install        # 首次执行
npm run dev
```

- 地址：http://localhost:3000
- 接口代理：`/dev-api` → `http://localhost:8080`（见 `.env.development` 的 `VITE_APP_BASE_API` / `VITE_APP_API_URL`）
- 首次启动较慢（需预构建依赖，约 30 秒），看到 `VITE ready` 即成功。

## 7. 第五步：启动用户门户（portal）

```powershell

```

- 地址：http://localhost:3100
- 接口代理：`/api` → `http://localhost:8080`（见 `portal/vite.config.js`）

## 9. 一键启动顺序

1. 启动 MySQL（系统服务）
2. 初始化数据库（仅首次）
3. 启动 MinIO（原生进程，9000/9001）
4. `mvn package` 打包后端 → `java -jar` 启动（8080）
5. `cd frontend && npm run dev`（3000）
6. `cd portal && npm run dev`（3100）

## 9.1 Docker 一键部署（可选）

项目已提供完整容器化方案，可一次性拉起 MySQL + MinIO + 后端 + 管理后台 + 门户。

```bash
docker compose up -d --build
```

| 服务 | 容器 | 地址 |
| --- | --- | --- |
| MySQL | `nougyou-mysql` | `localhost:3306` |
| MinIO | `nougyou-minio` | `localhost:9000`（控制台 9001） |
| 后端 | `nougyou-backend` | http://localhost:8080 |
| 管理后台 | `nougyou-admin` | http://localhost:3000 |
| 用户门户 | `nougyou-portal` | http://localhost:3100 |

说明：

- 首次启动 MySQL 会自动执行 `doc/zhongshan_farm_init.sql`（27 张表 + 演示数据）
- 涉及文件：`docker-compose.yml`、`backend/Dockerfile`、`frontend/Dockerfile`、`portal/Dockerfile`、`deploy/nginx/*.conf`、`deploy/maven/settings-docker.xml`
- MinIO 使用 `bitnamilegacy/minio`（官方 `minio/minio`、`quay.io/minio/minio` 已不再公开提供），并在 `command` 中显式开启 9001 控制台
- 启动前需确保端口 `3306/8080/9000/9001/3000/3100` 未被占用：本地 MySQL 服务（`MySQL80`）与原生 MinIO 需先停止
- 国内网络建议先给 Docker 配置镜像加速（`C:\Users\<用户>\.docker\daemon.json` 的 `registry-mirrors`，文件需为**无 BOM** 的 UTF-8），否则拉取镜像会失败
- 首次 `--build` 需在容器内编译后端与前端，耗时较长；后续构建会命中缓存
- 未配置 `GLM_API_KEY` 时容器会使用占位值（`sk-no-key-configured`）以保证服务能启动，此时 AI 客服不可用
- 可覆盖的环境变量（启动前设置）：

| 变量 | 说明 |
| --- | --- |
| `JWT_SECRET` | JWT 签名密钥（生产必须改） |
| `GLM_API_KEY` | 智谱 AI Key（不配则 AI 功能不可用） |
| `GLM_MODEL` | 模型名，默认 `glm-4-flash` |

- 若部署到服务器，需把 `docker-compose.yml` 中后端的 `MINIO_PUBLIC_ENDPOINT` 改成浏览器可访问的地址（如 `http://服务器IP:9000`），否则图片地址仍指向 localhost。
- 本地日常开发仍推荐第 3~7 节的原生方式（启动更快、支持热更新）。

## 10. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 页面一打开就报"系统异常" | 后端跑的是**旧 JAR**，新接口不存在 | 重新 `mvn package` 后重启 |
| `Non-resolvable parent POM ... connect timed out` | Maven 全局 settings 指向不可达私服 | 用 `-s settings-online.xml -gs settings-online.xml` |
| Vite 启动报 `crypto.hash is not a function` | Node 版本过低 | 升级到 Node 20.19+ / 22.12+ |
| 上传成功但图片打不开 | MinIO 未启动或 bucket 非公共读 | 先启动 MinIO；公共读策略由后端上传时自动设置 |
| AI 客服报错 / 无响应（401） | 未配置 `GLM_API_KEY` | 按 5.6 节通过环境变量配置真实 Key 后重启后端 |
| MinIO 启动报 `file access denied` | 数据目录无写权限 | 换到可写目录（如仓库内 `.minio-data`），或调整目录权限 |
| 登录提示"请输入验证码" | 验证码已开启 | 正常输入验证码；接口联调可临时关闭 |
| 端口被占用 | 上次进程未退出 | `netstat -ano | findstr :8080` 查到 PID 后 `Stop-Process -Id <PID> -Force` |
| 前端请求 401 | Token 过期（默认 120 分钟） | 重新登录 |
