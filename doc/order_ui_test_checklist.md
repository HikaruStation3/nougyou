### API-055 附加：支付宝沙箱支付（可选，需要先配密钥）

前提：按 `doc/alipay_sandbox.md` 填好 `app-id` / `private-key` / `alipay-public-key`，
把 `alipay.enabled` 改成 `true`，重启后端。浏览器 **Ctrl+F5** 强刷门户。

1. 下单后到订单列表点「去支付」。
   - **该看到**：弹窗里有「支付宝沙箱」和「模拟支付」两个按钮，并显示订单号与应付金额。
   - 如果只弹「模拟支付」：说明密钥没配对，弹窗会提示缺 `app-id` / `private-key` / `alipay-public-key` 中的哪几项。
2. 点「支付宝沙箱」→ 浏览器跳到 `openapi-sandbox.dl.alipaydev.com` 收银台。
3. 用**沙箱买家账号**登录 → 输入**沙箱支付密码** → 确认付款（不产生真实扣款）。
4. **该看到**：浏览器自动跳回 `/pay/result` 页面，显示「支付成功」。
5. 点「查看订单」：状态变 **待发货**，支付方式显示 **支付宝（沙箱）**，
   多出一行 **支付宝交易号**（形如 `2026...`）。
6. 回列表：这张单不在「待付款」里了。
7. 再点一次 `/pay/result` 页的「重新查询」：仍显示支付成功（幂等，不会重复扣款）。
8. 在收银台**不付款直接返回**：结果页显示「尚未完成支付」，订单仍是待付款，可再次发起。

> 沙箱密钥没配也不影响其它测试：不配就走模拟支付，弹窗会说明原因。
> 付款后支付宝可能有 1~3 秒延迟，结果页会自动重试 3 次。

## 4. 拆单验证（API-052 的多商家场景）

1. 确认购物车是空的（有残留先清空）。
2. 商品页加购：**米粉 ×1**（绿野农场）、**绿茶 ×2**（鲜果合作社）。
3. 顶部购物车 → 全选 → 「去结算」→ 确认订单页核对：米粉 ￥28 + 绿茶 ￥152 = ￥180。
4. 提交订单。
5. **该看到**：
   - 提示「已提交 **2** 个订单，请完成支付」；
   - 我的订单出现 **2 条不同订单号**：一条 ￥28.00 绿野农场，一条 ￥152.00 鲜果合作社；
   - 回购物车：已清空。
6. 把这两单分别取消（待付款 → 取消订单），把库存还回去。

> **避坑**：不要用「钟山笋干」测拆单。它处在委托代销中（委托方吴叔山货铺 → 受托方秀兰农场），下单会归到鲜果合作社，和绿茶合成 1 单，看起来像"没拆单"，其实是正确行为。

## 8. 三个容易卡住的地方

1. **找不到「去支付」**：先确认在「待付款」标签，按钮在订单卡片右下角；已支付的单不会再显示。
2. **刷新后店铺名没出现**：登录态缓存在 sessionStorage，退出重新登录一次即可。
3. **数据想复原**：手工测试会真实写库（订单、库存、销量都会变）。答辩前重新导入 `doc/zhongshan_farm_init.sql` 即可回到初始数据，或告诉我，我帮你写一个只清测试订单的脚本。
