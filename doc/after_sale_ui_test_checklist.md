# 售后服务模块手工测试清单（页面操作版 · API-061~066）

> 全程只点页面。主线：buyer01 申请 → farmer01 拒绝 → admin 平台介入改判退款。
> 分支覆盖：仅退款受理、退货退款回滚库存、换货、重复申请与越权。

## 1. 准备

1. buyer01 → 我的订单 → 找一笔与「绿野农场」交易的**已完成**订单（如 ZS202611267081）。
2. 先进详情页抄下商品当前**库存**（商品详情页可见），后面验证退货退款会加回库存。
3. 确认该订单商品行「售后」列为「-」，说明没有进行中的售后。

---

## 2. 主线：申请 → 拒绝 → 平台介入

### 2.1 买家提交（API-061 / 062 / 063）

1. buyer01 打开该订单详情 → 商品行点「申请售后」。
2. 类型选「仅退款」，退款金额默认等于小计 → 改成 **1.00**。
3. 申请原因填「商品破损」，描述随意，凭证可传 1 张图（复用文件上传接口）。
4. 提交 → 提示「售后申请已提交」。
5. 详情页出现「售后进度」区块：单号 `SH...`，状态**待处理**；商品行「售后」列变「待处理」。
6. 头像 →「我的售后」→ 列表能看到该单；按状态「待处理」筛选仍在；按单号搜索能命中。

预期：同一商品再次点「申请售后」应被拦截（按钮消失或提示已有处理中售后）。

### 2.2 商家拒绝（API-064 / 065）

1. farmer01 登录 → 头像 →「商家售后」→ 状态选「待处理」，能看到该单。
2. 点「处理」→ 选「拒绝申请」→ 不填意见直接提交 → 提示「拒绝售后时请填写处理意见」。
3. 填「商品已核实无破损」→ 确认 → 状态变**已驳回**。
4. 商家工作台「待处理售后」数字相应减少（点击卡片可直达商家售后页）。

### 2.3 平台介入（API-066）

1. admin 登录 → 左侧「售后处理」→ 状态选「已驳回」→ 找到该单。
2. 点「介入」→ 选「支持买家退款」→ 退款金额 1.00 → 裁定说明必填 → 确认。
3. 状态变**已完成**；商家侧刷新也为已完成。

### 2.4 结果核对

1. buyer01 订单详情 → 该商品行售后状态「已完成」，售后进度显示处理意见。
2. 订单支付状态仍为**已支付**（1 元为部分退款，未退满整单）。
3. admin 售后列表按「已完成」可查到该单。

---

## 3. 分支

### 3.1 退货退款回滚库存（API-061 / 065）

1. buyer01 另选一笔已完成订单商品，申请「退货退款」，金额 1.00。
2. 抄下该商品库存 → farmer01 受理并退款 → 状态「已完成」。
3. 回到商品详情：库存 = 原库存 + 该行购买数量。

### 3.2 换货不涉及退款

1. 申请「换货」，表单不显示退款金额，直接提交成功（申请金额 0）。
2. 商家受理后状态「已完成」，库存不变。

### 3.3 咨询类

1. 申请「咨询」，商家可直接受理或拒绝，流程同上，不动订单支付状态。

---

## 4. 异常与权限

| 场景 | 操作 | 预期 |
|---|---|---|
| 未登录 | 直接访问 `#/after-sales` | 跳登录页 |
| 重复申请 | 同一商品连续提交两次 | 第二次提示「已有处理中的售后」 |
| 金额超限 | 退款金额 > 商品小计 | 提交被拒，提示不能超过小计 |
| 买家越权 | buyer02 打开 buyer01 的售后详情 | 无权查看 |
| 商家越权 | farmer02 处理 farmer01 的单 | 无权处理其他商家的售后 |
| 管理员越权 | 买家调用后台介入接口 | 403 |
| 非驳回单介入 | 对「待处理」单尝试介入 | 提示仅已驳回可介入 |
| 未支付订单 | 待付款订单详情 | 不显示「申请售后」 |

## 5. 必过判定

- [ ] 提交后订单详情、我的售后、商家售后三处状态一致
- [ ] 商家拒绝后必须能从后台「售后处理 → 已驳回」筛到并改判
- [ ] 退货退款完成库存准确 +N，且只加一次
- [ ] 部分退款订单仍为「已支付」，全额退款才变「已退款」
- [ ] 买家 / 商家 / 管理员三端数据隔离，越权全部被拒
- [ ] 关闭浏览器重进，售后进度仍在（落库，不是前端临时状态）
